온비드 홈페이지는 이렇게 점검하고 있습니다

부서장님께 드리는 설명 자료 · 2026-11-06 · OnBid Ops Radar 홈페이지 모니터링

한 줄 요약. 시스템이 매시간 7분에 일반 이용자처럼 온비드 홈페이지에 접속해 보고, 다섯 가지를 차례로 확인합니다. 지금(11월 6일 13시 기준) 다섯 가지 모두 정상 입니다.

1. 먼저, 비유로 이해하기

매시간 누군가가 가게(온비드)에 직접 찾아가 보는 것과 같습니다.

① 가게 문까지 길이 열려 있나→ ② 문을 열면 들어가지나→ ③ 안에 물건이 제대로 진열돼 있나

여기에 참고용 확인 두 가지(입구 안내판이 보이나, 줄 세우는 번호표 기계가 켜져 있나)를 더해, 모두 5개 층이 됩니다. 앞의 세 층이 "홈페이지가 정상인가"를 결정하고, 뒤의 두 층은 문제가 생겼을 때 원인을 좁혀 주는 참고 정보입니다.

2. 다섯 개 층, 하나씩

L1

1층 · 접속 정상 판정에 반영

온비드 서버까지 통신 길이 열려 있는지, 그리고 보안 인증서(사이트가 진짜임을 증명하는 신분증)가 유효한지 봅니다.

이번 결과
정상 · 인증서 37일 남음
쉽게 말하면
가게까지 가는 길이 뚫려 있고, 가게의 영업 허가증이 37일 뒤까지 유효하다는 뜻입니다.
문제가 생기면
접속 자체가 안 되면 "실패"입니다. 이미 만료됐거나 잘못된 인증서도 "실패"입니다.
인증서 37일의 뜻
온비드 서버가 내미는 보안 인증서의 유효기간이 끝나기까지 남은 일수입니다. 37일은 아직 여유가 있다는 뜻입니다.
만료가 다가오면
남은 기간이 14일 이하가 되면 "인증서 만료 임박" 알림이 텔레그램으로 하루에 한 번 갑니다. 이 알림은 참고 신호라 홈페이지 정상/장애 판정은 바꾸지 않습니다.
L2

2층 · 홈페이지 열기 정상 판정에 반영

온비드 메인 화면 주소를 실제로 열어 보고, 서버가 "정상입니다(200)"라고 답하는지, 얼마나 빨리 답하는지 봅니다.

이번 결과
HTTP 200(정상 응답) · 응답 388ms(약 0.4초)
쉽게 말하면
문을 두드리니 0.4초 만에 "들어오세요" 하고 열어 줬다는 뜻입니다.
기준
3초 이내면 정상, 3초를 넘으면 "성능 저하", 10초를 넘으면 실패로 봅니다. 서버 오류 응답(500번대)이나 안내 페이지로 넘어가는 경우도 실패입니다.
최종 주소
접속이 끝난 곳이 의도한 메인 화면(main.do)임을 확인한 값입니다.
L3

3층 · 화면 내용 정상 판정에 반영

문이 열렸어도 안이 텅 비었거나 엉뚱한 화면이면 이용자는 쓸 수 없습니다. 그래서 화면 안에 꼭 있어야 하는 요소가 있는지 확인합니다.

이번 결과
정상
확인하는 것
  • "온비드" 제목, "조건검색", "공고검색", "회원가입", "로그인" 같은 핵심 메뉴 글자가 있는가
  • 화면을 움직이게 하는 핵심 프로그램 파일이 받아지는가
  • 화면 크기가 평소만큼 큰가(내용이 비어 있지 않은가)
  • "점검 중" 같은 안내문이 대신 떠 있지 않은가
쉽게 말하면
가게에 들어가 보니 간판, 진열대, 계산대가 모두 제대로 있다는 뜻입니다. 이 층이 있어서 "겉은 열리는데 속은 고장난" 상황도 잡아냅니다.
보조1

보조 · 진입 안내 페이지 정상 판정에 반영 안 됨

온비드 가장 앞쪽 입구 주소(www.onbid.co.kr)가 열리는지 가볍게 확인합니다.

이번 결과
HTTP 200 · 응답 38ms(아주 빠름)
왜 보나
메인 화면에 문제가 생겼을 때, 입구 자체는 열리는지 비교해서 원인이 어디인지 좁히는 참고 자료입니다.
판정에서 빠지는 이유
이용자가 실제로 쓰는 화면이 아니라 참고용이라, 이 값이 나쁘다고 해서 곧바로 "장애"로 세지 않습니다.
보조2

보조 · 대기열 설정 정상 판정에 반영 안 됨

접속자가 한꺼번에 몰릴 때 순서대로 줄을 세우는 장치(대기열)의 설정 파일이 정상적으로 읽히는지 확인합니다.

이번 결과
HTTP 200 · 응답 46ms
쉽게 말하면
입장객이 많을 때 나눠 주는 번호표 기계가 켜져 있는지 보는 것입니다.
왜 보나
입찰 마감 같은 붐비는 시간에 대기열 쪽이 고장나면 이용자가 막힐 수 있어, 원인 파악에 도움이 됩니다. 다만 이것만으로 홈페이지 전체가 장애라고 단정하지는 않습니다.

3. 한눈에 보기

층무엇을 보나이번 결과홈페이지 정상 여부 결정
1층 접속길이 열려 있나, 인증서 유효한가정상 (인증서 37일)예
2층 홈페이지 열기열리나, 빠른가정상 (0.4초)예
3층 화면 내용핵심 요소가 다 있나정상예
보조 진입 안내입구 주소가 열리나정상 (0.04초)아니오 (참고)
보조 대기열번호표 기계가 켜져 있나정상 (0.05초)아니오 (참고)
결론. 이번 점검에서는 "홈페이지 정상"입니다. 판정을 결정하는 1~3층이 모두 정상이고, 참고용 두 곳도 이상이 없습니다.

4. 문제가 생기면 어떻게 되나

  • 한 번 실패하면 바로 장애로 확정하지 않습니다. 잠깐의 흔들림일 수 있어 곧바로 한 번 더 확인하고, 계속 실패할 때 장애로 확정해 텔레그램으로 알립니다.
  • 이어서 어느 층에서 처음 막혔는지를 알려 줍니다. 예를 들어 1층에서 막히면 "접속 자체 문제", 3층에서 막히면 "열리지만 화면이 비정상"입니다. 보조 두 곳의 결과는 원인을 짚는 단서가 됩니다.
  • 온비드가 미리 알린 점검 시간은 사전에 등록해 두면 장애로 세지 않습니다. 예고 없는 장애 안내 화면이 뜨면 장애로 처리됩니다.
  • 1시간 동안 점검 기록이 끊기면 시스템이 스스로 이를 알아채고 별도로 경고합니다.

5. 인증서 만료 임박 시 해야 할 일

인증서는 사이트가 진짜 온비드임을 증명하는 신분증이고, 보통 1년 단위로 갱신해야 합니다. 갱신하지 않으면 만료되는 순간 이용자 화면에 "안전하지 않은 사이트" 경고가 떠서 서버가 멀쩡해도 사실상 접속이 막힙니다.

  • 알림이 오면: 온비드 운영 담당 부서·업체에 "인증서 갱신 일정이 잡혀 있는지" 확인합니다. (이 시스템은 대신 조치하지 않고 미리 알리는 역할입니다.)
  • 온비드 측 작업: 발급 기관에서 갱신·재발급 → 웹 서버와 앞단 장비(L4·로드밸런서 등 인증서가 올라간 모든 곳)에 설치 → 새 만료일 확인.
  • 권장 시점: 만료 한 달 전쯤 시작하는 것이 안전합니다. 현재는 37일 남아 있어 아직 조치할 필요는 없습니다.

6. 알아 두실 한계

  • 이 점검은 한 곳(서울 서버)에서 1시간에 한 번 보는 외부 관측입니다. 모든 이용자의 상태를 뜻하지 않습니다.
  • 점검과 점검 사이(최대 1시간)에 생겼다 사라진 짧은 문제는 보이지 않을 수 있습니다.
  • 로그인 이후 화면이나 입찰 같은 실제 업무 기능은 점검하지 않습니다. 홈페이지가 열리고 필수 요소가 있는지까지입니다.
  • 현재 1주일 시범 운영(관찰) 중이며, 오탐(실제로는 정상인데 장애로 본 경우)이 없는지 확인한 뒤 기준값을 조정할 예정입니다.
