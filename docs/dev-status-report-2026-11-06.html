3. 만든 것: 무엇이 가능해졌나

매시 :07 정시 점검→ 실패 시 90초 뒤 재확인→ 상태 전환·사건 판단→ 텔레그램 알림→ 이상징후(WEB) 기록

별도로: 10분마다 점검 프로그램 자체가 멈췄는지 감시(앱 없이 DB가 직접 알림), 하루 1회 보존 삭제와 일별 요약.

점검과 판정

  • 접속·응답·화면 내용 3단계 점검과 보조 확인(진입 스텁, 대기열)
  • 판정 6종, 확인 불가·미점검은 정상으로도 실패로도 세지 않음
  • 점검은 GET만, 허용 호스트 2개 밖으로 나가지 않음

알림과 사건

  • 장애·저하·지속·복구·인증서·점검 불가·미등록 점검·보조 이상·억제 알림
  • 같은 알림 중복 방지, 하루 알림 상한(12건), 실패 시 재발송
  • 정시 점검 정지 감지(130분) 후 정지·재개 알림 (앱과 독립)

화면과 운영 도구

  • /web: 상태, 24시간 띠, 점검 이력, 알림 기록, 경고 띠
  • 팀장: 계획 점검 창 등록·취소, 지금 점검
  • 이상징후 화면에 출처 WEB 필터·배지, 복구 확인됨 이력

안전장치

  • 꺼짐 스위치와 스케줄 해제, 롤백 절차 문서화
  • 알림 키·시도·이력은 추가 전용(삭제 불가)
  • 비밀값은 Vault·Vercel 두 곳에만, 출력은 모두 가림
